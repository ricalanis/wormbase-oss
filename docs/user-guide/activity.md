# `/activity` — User guide

## What it does

The Activity tab is the **member's daily home** — three live panels in one
view:

1. **Conversations feed** — recent threads + DMs the worm has observed,
   with the worm's running summary per thread.
2. **Tasks panel** — open tasks the worm has extracted from chatter ("Bob
   said he'd send the Q3 numbers by Friday").
3. **Insights panel** — the worm's recent observations: surfacing
   recurring questions, decisions about to be made, KPI movements.

This is the surface that makes the worm feel alive in the org without
any per-tab chasing. Members live here.

## First action

Open `/activity`. Without configuration:

1. The conversations feed renders the last 20 threads from connected
   channels, sorted by recency. Each thread carries: channel name, top
   participants, message count, the worm's summary (1-2 sentences).
2. Click any thread to expand inline — see the worm's per-message
   classification (decision / question / task / status update).
3. The tasks panel shows open tasks. Click **Mark done** to write
   `emit_task_resolved {outcome=done}`; click **Defer** for `outcome=deferred`.
4. The insights panel shows what the worm flagged as worth attention —
   click any insight to drill into the source thread.

## Advanced

- **Filter conversations by channel** — chip in the panel header.
- **Surface insights to a Person** — click any insight → **Send to
  @<person>**. Writes a worm DM to that Person with the insight payload.
- **Subscribe to a topic** — pin a topic from `/topics` and the
  conversations feed will boost threads matching that topic.
- **Insight classes** — recurring_question / decision_imminent /
  kpi_drift / process_deviation / source_drift. Each has a different
  color + icon. Configurable per Person via `/settings/notifications`.
- **Tasks aging** — tasks open > 7 days surface as **Stale**; > 30 days
  as **Forgotten**. The worm pings the assignee in chat after the
  forgotten threshold.

## Behind the scenes

Reads from three projections:

- `projection_conversations` — the silver-conversations layer; folds
  `emit_chat_received` + `emit_chat_summarized` per thread.
- `projection_tasks` — folds `emit_task_proposed`, `emit_task_assigned`,
  `emit_task_resolved`.
- `projection_insights` — folds the worm's observation entries
  (`emit_insight_*`).

The summary text on each thread is generated by the worm's summarizer
(commodity own-inference path, Gemma 4) on every Nth message in a thread.
The summary is replayable — pinned to the source `message_ids[]` it
covers.

Tasks are extracted by `apps/worm-core/src/wormbase_core/task_extractor.py`,
which runs on every new chat batch and writes `emit_task_proposed` when
a task pattern matches. Tasks auto-resolve when the worm sees the
matching follow-up ("here are the Q3 numbers" → resolves the "send Q3
numbers" task with `outcome=done`).

## Failure modes

| Symptom | Cause | Fix |
|---|---|---|
| Conversations feed empty | tenant has no connected channels | Connect Slack via `/channels` |
| Summaries say "..." | summarizer queue backed up | Check inference router latency; throttle is configurable |
| Tasks never auto-resolve | Worm couldn't link the follow-up | Mark resolved manually; or tune the extractor threshold |
| Insights missing | projection rebuild ran recently and reset state | Wait one autoresearch cycle for new insights |
| Worm's summary contradicts thread | LLM hallucination — gate is conversational, not deterministic | Click **Re-summarize**; writes `emit_chat_summarize_requested` |
