The agent-installable continuous lake

The agent-installable
continuous lake.

WormBase installs into your chat and your data lake — either by building one (default local) or by connecting to your existing lake. From the moment of install, the lake is continuous + agent-operated. The agent and the lake co-emerge: there is no lake before the agent is tending it. Eight lake-side loops continuously tend its state; every action is hash-chained from the ledger.

§ 01  /  capabilities

Five things the worm does, end‑to‑end.

01 · presence◆

Listens in chat first

Installs into your Slack workspace, auto-discovers your team across channels, and ingests files dropped in conversation. The chat stream is itself a lake surface — the conversation family — tended from the first message forward. Discord and Teams via the same ChannelAdapter contract; WhatsApp in preview. Lurks by default; speaks only when a relevance gate fires.

Listen · ingest · tend
02 · lake▲

Tends a continuous lake

The lake doesn't sit still after install — it is continuous, always being tended. Eight lake-side loops (L1 triage, L2 catalog drift, L3 lineage, L4 schema-impact, L5 semantic types, L6 classification, L7 quality, L8 entity stitching) run concurrently from t = 0 across every surface.

Build or connect via a single SurfaceDriver Protocol: 15+ lake surfaces today — in production (csv_local, postgres, snowflake, s3_csv, http_csv, stripe); coming soon (bigquery, salesforce, hubspot, gsheets, notion, linear, plus MCP presets). Bronze → silver → gold replays bit-exact.

Tend · build or connect · maintain
03 · install◇

Two installations, both agent-led

A WormBase install is two acts, not one. Chat install: @connect slack (or discord / teams). The worm acquires a tendable user-side surface — the conversation stream.

Lake install: build OR connect. Build is the default local path — the csv_local SurfaceDriver bootstraps ~/.wormbase/lake/{bronze,silver,gold}/ for prospects without a warehouse yet. Connect installs the agent into your existing lake via a SurfaceDriver (Postgres warehouse, Snowflake, BigQuery, S3 lakehouse, Notion via MCP, and so on).

Both paths end at the same substrate state. Both trigger the same propose → execute → verify → resolve ledger sequence. Both activate the same eight lake-side loops. The agent and the lake co-emerge from t = 0.

Chat · build or connect · co-emerge
04 · knowledge●

Compounds knowledge across 8 axes

The eight lake-side loops are the compounding axes: lineage, quality checks, schema-evolution impact, semantic-type fingerprinting, column classification, entity stitching, source-candidate triage, catalog drift. Cross-axis chains (L5 → L7, L6 → L4, L5 → L4) reinforce each other. Synthesis happens at ingest, not at retrieval.

Detect · classify · reinforce
05 · receipts■

Answers with receipts

Every answer carries the ledger entries that produced it. Hash-chained, replayable, auditable. Wire-replay feeds recorded infrastructure events back through the channel adapter for deterministic re-runs — same code path, different input source.

Trace · verify · replay
§ 02  /  substrate

Lake at the center, ledger below, everything else is a projection.

The diagram is the thesis. The continuous lake is at the center; four equal source families — conversation, external, filedrop, evidence — are kinds of faces of the lake, not a separate input box. Worm-core lives inside the lake as the tender, not outside it as a consumer. The Postgres ledger is below the lake: the substrate every action chains from.

WormBase reduces to a single write primitive and a single read primitive. The write primitive is PEVR: propose → execute → verify → resolve. Every persistent state change — a profile, a KPI, a person discovery, an answer, a surface acquired — flows through one of those four entry shapes. Both installations (chat via @connect slack and lake via build-or-connect) fire the same sequence; both activate the same eight lake-side loops.

The ledger is append-only, company-scoped, hash-chained. It is the substrate, not a side-channel. Lake, memory, KPI tree, channel history, gate outcomes are materialized projections over the ledger. Replay it to timestamp T and you reproduce any state — same hashes, same bytes — including the act of installing the surfaces themselves.

The conversational edge is LLM-driven and stochastic by design. The core writes are deterministic. The gate between the two is where trust is enforced. We do not trust the LLM — we trust the gate between the LLM and the substrate.

Governance follows the same shape: Person × Domain × Resource × Classification × Policy, all materialized from the ledger. No separate database, no portal, no workflow engine. Governance is code.

§ 03  /  get started

Two installations. One command to start.

§ 03.1 Aspirational. The Docker compose path is on the OSS release roadmap — follow along on GitHub.

WormBase runs as a small set of services: the worm-core hub, a Postgres for ledger and projections, an inference endpoint, and a channel-adapter for each connected platform. Bringing up the stack is one command; the two installations — chat (@connect slack) and lake (build or connect) — happen from the dashboard once it's up. A default local lake auto-provisions for the build path so you can see tending behaviors immediately. 

# clone the repo
$ git clone https://github.com/wormbase/wormbase.git
$ cd wormbase

# bring up worm-core, ledger, inference, channel-adapter
$ docker compose up

# open dashboard at http://localhost:3000, then:
#   1. chat install — @connect slack (or discord / teams)
#   2. lake install — build (csv_local default) OR connect
#                        (postgres / snowflake / s3_csv / stripe / ...)

Today, contributors run packages directly from the workspace (make test-all, make qa). See DEVELOPERS.md for the contributor path; the hosted compose path lands when the OSS release ships. The lake-surface catalog today covers csv_local, postgres, snowflake, s3_csv, http_csv, stripe; BigQuery, Salesforce, HubSpot, Notion / Linear / Atlassian (via MCP) and others land alongside the OSS release.
